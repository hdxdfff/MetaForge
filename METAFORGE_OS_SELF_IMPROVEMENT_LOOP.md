# MetaForge OS Self-Improvement Loop

This file defines the bounded self-improvement loop for MetaForge OS.

## Purpose

Improve the system without losing delivery continuity.

## Loop

1. Read self model.
2. Read CEO status.
3. Detect the top contradiction.
4. Select one bounded improvement target.
5. Choose implementation, proposal, or report mode.
6. Validate the effect.
7. Persist the result or failure.

## Bounded targets

Preferred targets:

- routing integrity
- verification return path
- dialogue lane coordination
- KPI visibility
- fallback continuity

## Output contract

Each self-improvement cycle must produce at least one of:

- patch proposal
- branch goal
- state report
- verification report
- low-risk wrapper or operator doc change

## Safety rules

- do not let self-upgrade silently rewrite product scope
- do not count provider-only output as success
- do not increase automation breadth when delivery integrity is broken
